# 回答实验记录

## 目的与方法

验证回答模块能否把检索片段作为唯一依据，给出可核对的回答：回答中的 `[n]` 必须对应交付片段，引用编号要和文件名、物理页码、原文一起展示，资料不足时要明确提示而不是硬凑。

回答由外部生成模型产生，自动检查只能发现“编号不存在”和“完全没有引用”，不能判断陈述是否真的被原文支持。因此每条回答都要按引用打开 PDF 人工核对。

## 实验条件

- 索引：`data/index-from14-384`（384 / 64 token，`--start 14`），与检索评测使用同一索引。
- 检索：dense top 20 → rerank top 5；另可用 `--dense-only` 比较只检索作为证据的差异。
- 生成模型：火山方舟 OpenAI 兼容接口，`glm-5.3-flash`，温度 0.1，最多 4096 输出 token（含推理内容）。
- 数据流向：问题和 5 条片段正文发送到 `https://ark.cn-beijing.volces.com/api/coding/v3`；PDF 文件、索引和其他文档不发送。费用按服务商规则产生，运行时以账户用量为准。
- 密钥：只从环境变量 `ARK_WORK_FLOW_API_KEY` 读取，不写入仓库、命令行或日志。

## 问题集

从 `docs/experiments/questions.json` 取 3 个文档内问题和 1 个文档外问题，答案页为人工标注的物理页码。

| id | 问题 | 答案页 |
|---|---|---|
| labor-overtime | 加班费、年休假该怎么算？ | 291–292 |
| labor-layoff | 被裁员能拿多少补偿？N、N+1、2N 有什么区别？ | 292–294 |
| baby-documents | 孩子刚出生要办哪些手续？ | 360–361 |
| outside-topic | 量子纠缠是什么？ | 无 |

`labor-unpaid` 在重排后答案页掉出前 5，可作为“证据不完整时会不会硬答”的补充检查；也可加 `--dense-only` 对比。

## 运行命令

```bash
export ARK_WORK_FLOW_API_KEY="你的密钥"
uv run python -m src.rag.cli.answering data/index-from14-384 "加班费、年休假该怎么算？" \
  --candidate-k 20 --top-k 5
```

其余问题替换最后一个参数即可。文档外问题预期回答明确说明资料中没有答案；如果模型仍给出书外知识，记为不符合。

## 结果（2026-10-30）

条件同上，索引 `data/index-from14-384`，重排后取前 5 条作为证据。判读标准：符合 / 部分符合 / 不符合，依据是逐条打开引用片段核对。

| id | 引用编号 | 判读 | 核对依据 |
|---|---|---|---|
| labor-overtime | [1] [2] [3] [4] | 符合 | 三档比例、审批与综合工时的说明、年休假 5/10/15 天、300% 含正常工资、21.75、离职折算和 1 年仲裁时效都能在 291–292、455 的原文找到；第 448 页清单页未被引用。 |
| labor-layoff | [1] [2] [3] [4] | 符合 | N 的算法与 3 倍封顶、N+1 的第四十条三种情形、经济性裁员没有“+1”、2N 的定义均在 292–293 原文；回答还如实说明个税内容未被片段展开。 |
| baby-documents | [1] [2] [4] | 部分符合 | 出生医学证明、居民医保、足跟血/听力筛查、维生素 K、安全座椅均有原文支持；但前 5 条没有 360 页，回答未给出“出生登记（落户）”的具体做法，只说明片段未展开。改用 `--dense-only` 后 360–361 进入证据，回答补上了出生登记和育儿补贴（每孩每年 3600 元），判读符合。 |
| labor-unpaid | [1] [2] [3] [4] [5] | 符合 | rerank 未取到 136–137 页，但 448–449、455 的清单页明确写了“先打 12333 投诉劳动监察，再申请劳动仲裁”，以及离职后 1 年时效、12348 法律援助、包工头找总包；回答与这些原文一致。 |
| outside-topic | [1] [2] | 符合（资料不足） | 明确回答资料中没有量子物理内容，并指出证据里的“纠缠”指治安管理处罚法中的骚扰行为，没有用书外知识补答。 |

引用编号全部落在交付的 5 条证据内，没有出现越界编号；程序对“未引用”和“无引用”的提示符合实际。`baby-documents` 的遗漏来自重排没有选入 360 页，不是模型编造；同一问题换 dense 证据后回答完整，说明“引用合法”不等于“答案完整”，证据集合本身也要核对。

### 实现中发现的问题

首次用 `max_tokens=1024` 运行时，`labor-overtime` 的回答在“且不能拿补”处被截断，引用检查仍照常执行。原因是该模型先输出推理内容、推理也计入输出上限。现在把默认上限提高到 4096，并在 `finish_reason=length` 时直接报错，不再交付半截回答；上述结果均为修正后重跑。

本地还曾用模拟的 OpenAI 兼容服务检查完整链路：请求发往 `/chat/completions`，请求体包含问题和全部编号片段，引用能对应到证据。该检查不验证真实模型的中文质量和忠实度。

## 人工核对点

1. 回答中的关键数字、条件和限定语是否能在引用片段中找到对应原文。
2. 引用编号是否指向真正支持该陈述的片段，而不是同主题的其他条目。
3. 文档外问题是否明确提示资料不足；有没有把召回片段当成答案依据。
4. 回答是否遗漏原文中的重要限定（例如适用范围、时效、例外）。
5. 程序提示的“未引用”“引用编号不存在”“来源无法核对”是否被如实处理。

## 限制

- 只有引用编号的机械检查，没有自动事实核查；回答正确性依赖人工判断。
- 问题仍按书中标题措辞拟，可能高估真实提问下的表现。
- 未做多轮追问、查询改写和长文档上下文压缩；单次只发送 top 5 片段。
- 每个问题只运行一次，没有重复采样，无法判断模型输出的稳定性。
- 未记录响应时间和实际费用；外部服务的可用性、限流和错误码也只在本次运行中观察到一次。
- 只有单一 PDF；换文档后需重新确认证据数量、页码和引用表现。
