# 重排实验记录

## 实现协议

日期：2026-10-30。

当前实现提供两种可对照模式：

- dense 基线：直接从持久化 `VectorStoreIndex` 取最终 `top_k`；
- 两阶段检索：dense 先取 `candidate_k=20`，再由本地 CrossEncoder 重新排序并交付 `top_k=5`。

重排结果继续使用索引中保存的 Node 正文、文件名、路径和 PDF 物理页码。输出同时保留 dense 原始排名和相似度分数，以及 rerank 新排名和重排分数；两类分数不在同一尺度上，不能直接比较。模型加载使用 `local_files_only=True`，问题和文档不会发送到外部服务。

## 可复现实验命令

默认模型路径集中配置在 `src/rag/config/common.py`，当前使用本机 Hugging Face 缓存中的 `BAAI/bge-reranker-v2-m3`。运行时无需传入重排模型路径；若要临时覆盖，可传 `--rerank-model-path`。历史实验用的全文索引已清理，复跑时先构建新索引（起始页按本文档前置页确定，换 PDF 时须重新确认）：

```bash
uv run python -m src.rag.cli.indexing build data/index-from14-384 docs/pdf/HowToLiveBetter.pdf --start 14
uv run python -m src.rag.cli.retrieval search data/index-from14-384 \
  "加班费、年休假该怎么算？" \
  --candidate-k 20 --top-k 5
```

使用同一问题增加 `--dense-only` 并设置 `--top-k 5`，即可得到 dense 基线。实验应固定索引、嵌入模型、问题和最终输出数量，只比较是否启用重排。

## 当前状态

核心逻辑和 CLI 已通过自动化测试，覆盖候选重新排序、原始排名保留、dense 实际返回候选少于请求数、最终数量超过实际候选数、本地模型路径检查和加载参数、非标量分数拒绝以及禁止静默退回 dense。

## 人工对照结果（2026-10-30）

### 实验条件

- 索引：`data/index-full-384`，由 `docs/pdf/HowToLiveBetter.pdf` 全量构建，切片 384 token、重叠 64 token。
- 嵌入模型 `BAAI/bge-small-zh-v1.5`，重排模型 `BAAI/bge-reranker-v2-m3`，均本地 CPU 推理。
- 两种模式使用同一索引、同一问题、`--candidate-k 20 --top-k 5`，只切换 `--dense-only`。
- 表内页码为 PDF 物理页码，`原始排名` 是重排前在 20 条 dense 候选中的位置。

```bash
uv run python -m src.rag.cli.retrieval search data/index-full-384 "<问题>" --dense-only --top-k 5
uv run python -m src.rag.cli.retrieval search data/index-full-384 "<问题>" --candidate-k 20 --top-k 5
```

### 结果

人工判读标准：✓ 直接回答该问题；△ 相关但不是答案（交叉引用、同主题其他条目）；✗ 无关。

| 查询 | 模式 | Top 5 物理页码（重排模式括号内为原始排名） | 判读 |
|---|---|---|---|
| 加班费、年休假该怎么算？ | dense | 291 / 291 / 291 / 291–292 / 291 | 5✓ |
| 同上 | rerank | 291(2) / 291–292(4) / 4–5(17) / 455(9) / 291(1) | 3✓ 2✗ |
| 被裁员能拿多少补偿？ | dense | 299 / 220 / 448–449 / 292–293 / 292–293 | 2✓ 2△ 1✗ |
| 同上 | rerank | 292(11) / 292–293(5) / 300(9) / 448–449(3) / 299(1) | 2✓ 2△ 1✗ |
| 孩子刚出生要办哪些手续？ | dense | 360–361 / 361–362 / 361 / 450 / 12–13 | 2✓ 2△ 1✗ |
| 同上 | rerank | 450–451(20) / 449–450(13) / 361(3) / 193(11) / 12(9) | 2✓ 2△ 1✗ |

### 逐条观察

- **加班费、年休假**：dense 前五条全部是答案。重排把第 4–5 页的**全书目录**从第 17 名提到第 3 名——该页只出现小节标题「加班费、年休假该怎么算」，不含答案，属于词面重合造成的假阳性；同时把两条直接答案（dense 第 3、5 名）挤出前五。这是三条中唯一明确倒退的查询。
- **裁员补偿**：两种模式命中数相同。重排把「经济补偿 N 的算法、月工资封顶」从第 5 提到第 2，并把竞业限制补偿这条噪声挤出前二；代价是第 1 名换成「试用期违法做法」，与补偿金额无关。净效果略好于 dense。第 300 页片段是经济补偿金的个税说明，与「到手多少」相关，不是误召回。
- **新生儿手续**：两种模式命中数相同，但 dense 的 1、2 名正是《出生医学证明》和出生登记这两个标准答案；重排把它们都挤出前五，换上来的是乙肝疫苗、维生素 K、筛查、居民医保这类「也要办但非第一顺位」的条目。净效果差于 dense。

### 结论

三条查询里，重排一次明确倒退、一次略好、一次在命中数相同的情况下丢掉最直接的答案。**当前不能声称两阶段检索优于 dense 基线**；样本只有三条查询、单一 PDF、人工判读，也不足以给出通用结论。

### 发现的共性问题

1. **切片边界切进引文块。** 多条结果的开头是上一条的「来源 / 证据等级 / URL」，例如片段以「劳动合同法（第十九、二十、二十一、八十三条）. http://www.gov.cn/...」开头，正文在后面。这类片段同时污染 dense 和 rerank，也是重排被法条名称带偏的可能原因。改进优先级高于调重排参数。
2. **目录页和「口径」页会被词面重合命中**（第 4–5、12 页），两种模式下都会偶发。
3. **rerank 分数不可跨查询比较。** 三条查询的最高分分别为 0.96、0.42、0.94，而高分查询里排第 5 的仍是正确答案。因此不能设统一阈值，也不能把分数当置信度。

### 限制与后续

- 未记录耗时；未做文档外问题（应明确返回低相关或无结果）。
- 要得出可复现结论，应固定 dense top 20 候选，人工标注哪些片段是答案，计算命中率或 MRR，而不是只凭单次 top 5 的观感。
- 重排只能处理 dense 已召回的 20 条候选；如果相关片段没有进入候选集，应单独评估 hybrid 或其他召回策略。
- 在修正切片边界之前，不建议把重排作为默认行为。

## 修正切片边界后复测（2026-10-30）

### 改动

- 切片改为结构块优先：片段不再从句子或「来源 / 备注」行中间开始（见[切片实验记录](chunking.md)）。
- 索引换为 `data/index-from14-384`，384 / 64 token，`--start 14` 跳过目录、前言和各节简介（见[索引实验记录](indexing.md)）。
- 其余条件不变：同一 PDF、同一组问题、`--candidate-k 20 --top-k 5`、本地 CPU。

### 结果

判读标准同前：✓ 直接回答该问题；△ 相关但不是答案；✗ 无关。

| 查询 | 模式 | Top 5 物理页码（重排模式括号内为原始排名） | 判读 |
|---|---|---|---|
| 加班费、年休假该怎么算？ | dense | 291 / 291 / 291 / 291–292 / 292 | 5✓ |
| 同上 | rerank | 291(1) / 291–292(4) / 291(3) / 455(8) / 448(13) | 3✓ 2✗ |
| 被裁员能拿多少补偿？ | dense | 292 / 293 / 448–449 / 298 / 220 | 2✓ 2△ 1✗ |
| 同上 | rerank | 292(1) / 300(12) / 299(7) / 293(6) / 299–300(9) | 4✓ 1✗ |
| 孩子刚出生要办哪些手续？ | dense | 360–361 / 361 / 451 / 302 / 193 | 2✓ 2△ 1✗ |
| 同上 | rerank | 450–451(6) / 361(12) / 302(4) / 193(5) / 449–450(16) | 1✓ 2△ 2✗ |

### 逐条观察

- **加班费、年休假**：dense 五条仍是答案。重排把上一轮排第 3 的目录页挤掉，但换上来两条「清单页」——第 455 页（换工作、换城市的办理清单）和第 448 页（被裁后先做什么）。这两页按时间罗列各节条目，词面和「怎么算」接近，不含具体算法。
- **裁员补偿**：重排把个税（第 300 页）、计算步骤（第 299–300 页）从候选第 9、12 名提到前五，命中数从 2 变 4，是三条里唯一明显改善的。dense 的第 298 页是工亡待遇（113 万），与裁员补偿无关。
- **新生儿手续**：dense 前两名是出生医学证明和出生登记。重排保留第 361 页，却把章节首页（第 302 页）和「养不了怎么办」的收养登记（第 193 页）排进前五，命中数下降。

### 结论

- 目录页和各节简介的假阳性消失，结构切片达到了预期效果：抽查片段不再从句子中间开始；以引用行（`‣ 全国人大常委会…`）开头的片段后面接着正文，不再是纯引用碎片。
- 重排仍不是稳定收益：一次明显改善、两次变差。**当前不能声称两阶段检索优于 dense 基线**，也不建议设为默认行为。
- 新的假阳性来源是「清单页」（第 448–451、455 页把各节条目按时间排成步骤）。它们含做法但不含数字和依据，是否排除或按片段类型过滤，留待后续决定。

### 未验证

- 仍以单次 top 5 的人工判读为依据，没有对 dense 20 条候选逐条标注、计算命中率或 MRR。
- 文档外问题（预期返回低相关或明确无结果）尚未测试。
