运行命令见 README。观察输出：256 / 64 的片段 1 末尾至片段 2 开头有重复的「出国、旅行与境外安全」附近内容；片段 2 末尾停在「24.」，下一片段从标题开始，边界切开了编号和标题。128 / 32 的片段 1 末尾也在「20.」处断开，下一片段从标题开始，表明配置的重叠并非保证每个边界都有重复。中文可读，PDF 提取的行内换行仍保留；本次观察未替代对照 PDF 的人工验收。第 2 页的目录包含大量点线，128 / 32 产生 86 个片段，许多片段主要是点线，说明这种布局不适合直接按默认句子边界切分。

以上为修改前单页实验。较大切片在此页减少片段数量并保留更多上下文，但每个片段混合更多主题；较小切片更细，部分编号与标题分离。当前实现支持连续页面跨页切片，尚未评估检索质量；不同参数的节点 ID 不稳定，不应作为跨运行的持久标识。请使用者对照原 PDF 检查至少一组相邻片段及跨页边界，并记录判断后确认本阶段。

2026-10-29 跨页检查：同一 PDF 物理页 4–5，128 / 32 token，生成 26 个片段，长度最小 / 最大 / 平均为 42 / 128 / 99.2 token。片段 14 标记为物理页 4–5，包含页面边界两侧的文字，也包含提取出的页码及页眉；需要对照原 PDF 判断阅读顺序和这些噪声的影响，尚未评估检索质量。

2026-10-29 来源位置修复后，以相同的第 4–5 页比较带偏移量的适配器和原始 `SentenceSplitter`：128 / 32 均为 26 个片段，256 / 64 均为 13 个片段，两组文本逐片一致。这只是对当前文档和参数的检查；适配器使用 LlamaIndex 内部合并接口，升级依赖后须重新验证。

2026-10-30 结构边界切片：PDF 提取的正文只保留单换行，LlamaIndex 默认段落分隔符 `\n\n\n` 不生效，句子切分会切进「来源 / 证据等级 / 备注」这类行。现在先用行首符号（`• ‣ · ▪ ● ○ ◦`、`- `、`* `、编号条目 `1.` / `1、`）划出结构块，块不超过 `chunk_size` 时整体作为一个切分单元，超长块再交回 `SentenceSplitter` 按句子切分。结构块都是原文的连续片段，字符偏移量和页码溯源不受影响。规则在 `src/rag/config/chunking.py` 的 `STRUCTURE_BLOCK_START_REGEX`，只匹配行首符号，不依赖文件名、页数或内容。

在物理页 291–292（384 / 64）抽查：片段起点由句子中间变为「‣ 全国人大常委会…」「• 收益：…」「• 备注：…」「2. 年休假…」等块首，来源行不再被拆到两个片段。限制：`①`、`(1)`、靠缩进表示的条目不匹配，仍按句子切分；超长块回退到句子切分后，片段仍可能从 URL 中间开始。
