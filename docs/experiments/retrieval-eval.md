# 检索评测记录

## 目的与方法

单次 top-5 的观感无法回答“答案页到底有没有被召回、排在第几”。这里把问题、答案页和检索结果固定下来，用同一组问题比较 dense 和重排，作为后续调参和引入 hybrid 的基线。

答案页由人工逐页阅读 PDF 后标注，页码为物理页码（从 1 开始）。问题集在 `docs/experiments/questions.json`，评测命令读取同一份文件，避免文档和脚本各记一份。

## 指标

- **候选内**：答案页是否出现在 dense 的 20 条候选里。区分“没召回到”和“召回到了但排不上去”。
- **dense / rerank 名次**：答案页在前 5 条中第一次出现的位置。片段可能跨页，按页码集合是否相交判断。
- 名次命中只说明答案页被检索到，不说明片段真的支持答案；每条仍需人工核对原文。

## 结果（2026-10-30）

条件：索引 `data/index-from14-384`（384 / 64，`--start 14`），嵌入模型 `BAAI/bge-small-zh-v1.5`，重排模型 `BAAI/bge-reranker-v2-m3`，本地 CPU，`--candidate-k 20 --top-k 5`。

| 问题 | 候选内 | dense 名次 | rerank 名次 |
|---|---|---|---|
| labor-overtime | 是 | 1 | 1 |
| labor-overtime-paraphrase | 是 | 1 | 1 |
| labor-layoff | 是 | 1 | 1 |
| labor-unpaid | 是 | 4 | 未进前五 |
| baby-documents | 是 | 1 | 2 |
| credentials-phone-lost | 是 | 2 | 1 |
| housing-deposit | 是 | 1 | 1 |
| **汇总（7 题）** | **7/7** | **7/7** | **6/7** |

书外问题 `outside-topic` 的最高重排分是 0.0065，文档内七题的最高重排分在 0.78–0.97 之间。

## 观察

1. **dense 在这组问题上已经很强**：7 个文档内问题的答案页全部进入 20 条候选，并且全部落在前 5。当前瓶颈不是召回，而是重排在个别问题上打乱顺序。
2. **重排只在一题上退步**：`labor-unpaid` 的答案页在 dense 排第 4，重排后掉出前 5，被第 448、455 页两条“清单页”顶掉。这和人工复测的结论一致：重排模型偏好按时间罗列步骤的清单页，它们字面和“该怎么办”高度重合，但只是索引，不是依据。
3. **书外问题有区分度**：最高重排分 0.0065，与文档内问题相差两个数量级。但程序目前没有阈值逻辑，仍会照常返回候选；是否加阈值需要更多样本，且不能只看分数。
4. **方法限制**：这些问题是在读过正文之后、按书中标题措辞拟的（例如“N、N+1、2N”直接来自小节标题），与正文词汇重合度高，可能高估真实提问下的召回。要更可信，需要补充不借用原文措辞的问法，以及第二份 PDF。

## 复现

```bash
uv run python -m src.rag.cli.retrieval evaluate data/index-from14-384 docs/experiments/questions.json \
  --candidate-k 20 --top-k 5
```

输出每个问题的答案页、是否进入候选、两种模式下的名次，以及各自前 5 条的页码。修改问题集或索引后重跑同一命令即可对比。
