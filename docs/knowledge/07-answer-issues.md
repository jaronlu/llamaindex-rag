# 基于来源的回答：已实现能力及生产待办

记录日期：2026-10-30。当前实现用于学习和分阶段验证，尚未作为生产方案交付。回答质量依赖检索证据、提示词和外部模型，程序只能核对引用编号，不能自动确认陈述正确。

## 已实现

| 能力 | 当前做法 | 边界 |
| --- | --- | --- |
| 证据构造 | 复用 dense 或重排结果，按交付顺序编号为 `[1]…[n]`，每块带文件名、物理页码和完整正文。 | 只使用前 `top_k` 条片段，不重新解析 PDF；证据不足时无法补充其他页。 |
| 回答约束 | 系统提示要求只依据证据、关键结论标注 `[n]`、证据不足时明确说明，不得编造页码或原文。 | 提示词不能保证模型遵守；回答仍可能漏引、错引或混入书外知识。 |
| 外部模型接入 | 通过 LlamaIndex `OpenAILike` 调用 OpenAI 兼容接口，默认火山方舟 `glm-5.3-flash`；模型和地址可用 CLI 临时覆盖；温度和输出上限集中在配置文件。 | 问题和片段正文会发送到外部服务并产生费用；只在火山方舟上实跑过，未验证其他服务商的字段差异。 |
| 密钥处理 | 只从环境变量读取，默认 `ARK_WORK_FLOW_API_KEY`；支持 `--api-key-env` 改名，不写入命令行、配置或日志。 | 没有密钥托管、轮换、按用户隔离或最小权限方案。 |
| 引用检查 | 解析回答中的 `[n]`，标出被引用和未引用证据；编号越界、完全没有引用、被引证据来源无法核对都会明确提示。 | 只检查编号是否存在，不判断该片段是否真的支持对应陈述；PDF 原文中的 `[数字]`（如法条编号）被模型照抄时也会被当成引用，触发“不存在的证据编号”提示，仅提示、不阻塞，需人工区分。 |
| 异常与边界 | 无片段时不调用模型，直接提示资料不足；空回答、鉴权失败、网络错误和 `finish_reason=length` 截断都作为失败报错，不交付半截回答。 | 截断检测依赖服务端正确返回 `finish_reason`；其它异常原因仍由用户阅读错误信息判断。 |
| 输出可核对性 | 展示回答、引用检查，以及每条证据的文件名、来源路径、物理页码、片段 ID 和完整原文。 | 回答正文本身不含页码，读者要借助 `[n]` 回到证据区再查 PDF。 |
| 实跑与测试 | 4 个文档内问题和 1 个书外问题已实跑；文档内 3 题符合、1 题因重排漏证据而部分符合（dense 补跑后符合）、书外问题正确提示资料不足。自动化测试覆盖提示词、引用解析、截断、空证据和密钥缺失。 | 多数问题只跑一次，`labor-unpaid` 复跑两次且回答措辞不同；真实费用和延迟未记录。 |

运行命令见 [README](../../README.md)。真实运行的条件、逐题判读和限制见 [回答实验记录](../experiments/answering.md)。

## 生产场景尚未实现或验证

| 问题 | 影响与后续方向 |
| --- | --- |
| 忠实度评估 | 没有 claim 级蕴含检查、自动 faithfulness 指标或人工标注流程；引用编号合法不代表陈述被原文支持。需要按句核对、抽样评审和回归集。 |
| 资料不足判定 | 完全依赖提示词和模型自觉；检索通常仍会返回候选，只有候选全部被来源和正文校验过滤时 CLI 才直接提示资料不足、不调用模型。程序没有基于分数的相关性阈值、证据覆盖度或拒答策略。书外问题只验证了一题。 |
| 提示注入与恶意文档 | 片段正文按原样拼进提示词，没有分隔符、指令隔离或输出约束测试；文档内的指令可能诱导模型偏离系统提示。需要把证据当数据处理，并补充攻击样例。 |
| 敏感数据与合规 | 没有 PII 识别、脱敏或按文档配置的发送许可；片段会离开本机，生产环境需明确数据分级、授权、留存和供应商条款。 |
| 上下文与成本 | 没有统计提示词 token 数，也未按模型上下文窗口校验；`top_k`、`max_tokens` 只给出上限，没有预算、配额或单次成本记录。证据较多时可能超限或被拒。 |
| 检索依赖 | 回答质量受 top 5 证据限制：`baby-documents` 因重排漏掉 360 页而遗漏出生登记，换 dense 证据后才完整。检索、重排和回答需要一起评估，不能只看回答表面是否通顺。 |
| 多轮与改写 | 不支持追问、指代消解、查询改写或分解；复杂问题只能单轮回答。PRD 的进阶实践只列出查询改写或分解等能力，没有列出多轮追问和指代消解，这些均未实现。 |
| 可复现性 | 温度 0.1 但未固定 seed，也没有重复采样；同一问题的输出可能变化。需要保存模型版本、提示词版本、证据集合和运行参数。 |
| 服务可用性与重试 | 只配置 60 秒超时，未显式设置重试次数；SDK 默认重试可能在失败时重复发送并重复计费。没有熔断、降级或本地模型回退。 |
| 模型可移植性 | 只验证了 `glm-5.3-flash` 的 `reasoning_content` 字段、`finish_reason` 和输出上限行为；换模型或服务商后需重新确认这些字段和计费方式。 |
| 评测范围 | 只有一份 PDF、5 个问题，除 `labor-unpaid` 外均为单次运行；问题按书中标题措辞拟，可能高估真实提问表现。需要第二份文档、真实问法、重复运行和人工评审记录。 |
| 界面与审计 | 命令行输出适合人工检查，但没有交互式跳转、引用高亮或请求审计；生产环境需要记录发送了哪些片段、模型返回了什么，同时避免泄露敏感内容。 |

以上是待实现或待验证的方向，不代表已经发生线上故障，也不预设具体模型、服务商或合规方案。
